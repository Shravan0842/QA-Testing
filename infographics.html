1. QA vs QC

Quality Assurance is about improving the process to prevent bugs. Quality Control is about finding bugs in the product.

2. Seven Testing Principles

ISTQB's seven timeless truths — the foundation of every testing decision you'll ever make.

3. SDLC Models

Waterfall flows once. Agile loops. Pick the one your team and your project can actually finish.

4. STLC — 6 Phases

The Software Testing Life Cycle starts before code is written and ends after the release is closed.

Lifecycle

5. The Test Pyramid

Lots of fast unit tests, fewer integration tests, and very few slow end-to-end tests. Inverted pyramids are expensive.

Levels

6. Four Test Levels

Unit, Integration, System, UAT — each level zooms out one notch, and each one catches a different class of bug.

Levels

7. Functional vs Non-Functional

Functional tests check what the software does. Non-functional tests check how well it does it.

Foundations

8. Equivalence Partitioning

Group inputs that should behave the same. Test one value from each group — it represents the whole partition.

Techniques

9. Boundary Value Analysis

Most defects hide at the edges of valid ranges. Test the value just below, on, and just above each boundary.

Techniques

10. Decision Table Testing

Map every combination of inputs to the action that should fire. Catches logic bugs your test cases miss.

Techniques

11. Bug Lifecycle

New → Assigned → Open → Fixed → Verified → Closed. Reopen and Rejected are the two side doors.

Bug life

12. Severity × Priority

Severity is impact. Priority is timing. A typo on the homepage is high priority, low severity. A crash nobody can hit is high severity, low priority.

Bug life

13. V-Model

Each development phase has a matching test phase. The deeper the design, the deeper the test.

Lifecycle

14. Scrum Sprint Flow

Pick work. Plan. Build for 2–4 weeks. Review the demo. Inspect how you worked. Repeat.

Agile

15. Definition of Done

A shared checklist the whole team agrees means "this story is finished." If any box is unchecked, it's not done.

Agile

16. Test Case Anatomy

ID, title, pre-conditions, steps, expected result, post-condition. If any field is missing, it isn't a real test case.

Techniques

17. Test Plan Structure

The test plan is the contract. It defines scope, schedule, resources, and the entry/exit gates each phase needs to cross.

Lifecycle

18. API Request & Response

Client sends an HTTP verb + path. Server replies with a status code and a body. The middle is what testers break.

API

19. HTTP Status Codes

2xx is the win. 3xx is a polite nudge. 4xx is the client's fault. 5xx is the server's fault. The first digit is the headline.

API

20. Web vs Mobile Testing

Web has fewer browsers and bigger screens. Mobile has thousands of device + OS combos, shaky networks, and a battery that can die mid-test.

Mobile

21. Performance Test Types

Load test simulates expected traffic. Stress test tries to break it. Spike test slams it in bursts. Each one answers a different question.

Non-functional

22. Automation Pyramid

Automate the small, fast, reliable tests at the bottom. Save slow UI tests for the few flows only humans really need.
