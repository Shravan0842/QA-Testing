SDLC Models — one-liners:

  • Waterfall: Linear; each phase completes before next; testing at the end.
  • V-Model: Waterfall + testing mirrored at each level; testing planned early.
  • Agile: Iterative sprints; continuous testing & feedback; adapt to change.
  • Spiral: Risk-driven repeated cycles.

-- Filter rows

FROM customers c
JOIN orders o ON c.id = o.customer_id;

-- Count & group
SELECT city, COUNT(*) FROM customers
GROUP BY city HAVING COUNT(*) > 5;

✏️ Test Design Techniques — Cheat
  • BVA (Boundary Value Analysis): test values at, just below, just above boundaries. Field 18–60 → test 17, 18, 60, 61.
  • EP (Equivalence Partitioning): split inputs into groups; test 1 value per group. Valid 0–100 → test 50; invalid → -5 and 150.
  • Decision Table: combinations of conditions & outcomes (best for business rules).
  • State Transition: valid/invalid state changes (e.g., Pending → Paid → Delivered).
  • Error Guessing: intuition-based — empty fields, special chars, rapid clicks, huge data.
  • Pairwise Testing: test all combinations of variables pairwise to reduce test count.
⚠️ Interview"For an age field accepting 1–100: EP → test 0, 50, 101. BVA → test 0, 1, 100, 101." — know this cold.
📊 Estimation, Entry/Exit & Metrics — Cheat

Estimation techniques:

  • Functional Point Analysis
  • Use-Case based
  • Test Point Analysis
  • Experience based

Entry criteria (START when):

  • Build deployed & testable
  • Environment + test data ready
  • Requirements & test cases reviewed

Exit criteria (STOP when):

  • All critical/major bugs closed
  • All planned tests executed
  • No P1 blockers, summary report signed off

Key metrics:

  • Test Case Pass % = (Passed ÷ Total Executed) × 100
  • Defect Density = Defects ÷ KLOC
  • Defect Removal Efficiency (DRE) = Defects found ÷ (Defects found + missed in production)

💬 Top Interview Answers — One-Liners
Q: What is the difference between smoke and sanity testing?
Smoke checks that the whole build is testable (wide, critical features), while sanity checks one specific fix works (narrow).
Q: Regression vs Retesting?
Retesting re-runs the exact failed test case to verify a fix; regression tests the rest of the app to ensure nothing broke.
Q: What is the bug lifecycle?
New → Assigned → Open → Fixed → Retest → Closed, with possible Reopened, Deferred, or Rejected states.
Q: Severity vs priority?
Severity is how bad the bug is for the system (set by tester); priority is how urgent to fix (set by PM/business).
Q: What is a test plan?
A document covering scope, approach, resources, schedule, entry/exit criteria, and risks for testing a project.
Q: What is the STLC?
Software Testing Life Cycle: Requirement analysis, Test planning, Test case development, Environment setup, Execution, Closure.
Q: What is a traceability matrix?
A mapping of each requirement to its test cases and bugs, proving full coverage.
Q: When do you stop testing?
When exit criteria are met: all planned tests executed, critical bugs closed, risk acceptable, and report signed off.
Q: What is your role in a Scrum team?
Test stories in-sprint, write test cases from acceptance criteria, log bugs, do regression, demo quality at sprint review.
